# 智能放牧研究概览

!!! tip "用一句话理解研究任务"

    让机器人影响羊群运动，把羊群引导到目标区域；既要看有没有到达，也要看过程中是否出现分散、干扰或不安全的动作。

> 研究问题：如何通过机器人的运动，引导羊群进入指定区域？


## 看图梳理

![放牧机器人的研究问题](../assets/learning/herding-index.svg){ .learning-figure }

[打开大图](../assets/learning/herding-index.svg)

**理解羊群**：行为建模与感知，位置、速度、聚散状态；**选择行动**：仿真与放牧策略，把羊群引向目标区域；**检验效果**：成功率、时间、干扰，保留失败与边界案例。


## 任务与边界

以宇树 Go2 四足机器人为研究平台，先在仿真中研究放牧决策。将高层引导策略与底层运动控制分开，便于定位失败原因。以下是研究规划，尚未记录完成的实验结果。

## 从环境到策略

### 初学先画一张场景，不急着选算法

画出机器人、三只羊和一个目标区，约定所有位置都是同一坐标系中的米制坐标。接着回答：机器人现在知道哪些位置，下一步允许去哪，羊群会怎样响应，到哪种情况就结束？这四个问题分别帮助明确观测、动作、环境规则与回合边界。

“羊群中心更接近目标”可以作为反馈之一，但不能替代全部任务：两只羊已到目标、一只掉队时，中心也可能看起来不错。因此先记每只羊的位置与是否进入目标区，再考虑怎样压缩成观测与设计奖励。

羊群模型是为学习而设的近似规则，不是真实羊的完整行为。模型可以先只表达聚集、避让和机器人影响；记录这些假设，再用不同参数检查策略是否过于依赖某一种规则。

### 先手算一帧，弄懂“羊群状态”

设机器人在 `(2, 0)`，三只羊在 `(4, −1)`、`(4, 0)`、`(4, 1)`，目标区中心为 `(10, 0)`；坐标单位统一为米，x 轴向东、y 轴向北。

**羊群中心**就是把每个坐标分别求平均：x 为 `(4 + 4 + 4)/3 = 4`，y 为 `(−1 + 0 + 1)/3 = 0`，所以中心是 `(4, 0)`。中心到目标是 6 米；三只羊到中心的距离分别为 1、0、1 米，最远距离为 1 米。

| 状态描述 | 本例结果 | 它还没有告诉我们什么 |
| --- | --- | --- |
| 羊群中心 | `(4, 0)` 米 | 每只羊具体在哪 |
| 中心到目标距离 | 6 米 | 是否有羊落在后面 |
| 最大离群距离 | 1 米 | 羊是正在靠拢还是继续散开 |
| 羊的速度 | 本例尚未提供 | 至少还需时间上的运动信息 |

“状态压缩”就是把每只羊的许多数据变成较少的描述数值，方便策略处理。但压缩也会丢失信息，不能认为一个中心点就完整代表整个羊群。羊数量改变时，固定长度观测怎样处理、缺失目标怎样标记，也要在接口中说清。

| 环节 | 需要明确的问题 | 建议产物 |
| --- | --- | --- |
| 羊群建模 | 个体如何聚集、避让和响应机器人？ | 行为规则与参数说明 |
| 仿真环境 | 场地、障碍和目标区如何定义？ | 可复现的场景配置 |
| 状态观测 | 是否使用真实位置或视觉估计？ | 观测字段与坐标系 |
| 动作空间 | 输出目标点还是机器人速度？ | 动作范围与控制频率 |
| 奖励设计 | 如何同时衡量到达、聚集和效率？ | 奖励项与权重记录 |
| 策略评估 | 不同初始条件下是否仍然有效？ | 多次运行的统计结果 |

### 羊群行为模型：把假设与事实分开

在简化仿真中，可以先假设“太靠近邻居会远离，离群较远会靠拢，机器人接近时会产生避让倾向”。这些是建模思路，并不是对真实羊在所有条件下的保证。响应的距离、强度和延迟都需要参数说明。

初学先观察**同一条机器人轨迹会让羊群怎样变化**，再加入学习策略。若场景里的羊本来就会自动走到目标，策略可能什么也不做就获得高分；如果羊对机器人完全没有响应，策略再复杂也无法通过移动影响它们。先查环境有没有把我们要研究的因果关系表达出来。

### 高层决策与底层执行怎样分工

高层可以提出“移动到羊群后方某个点”的目标，也可以输出有界速度。底层负责依据机器人能力跟踪这些要求。目标点、速度、关节控制是不同层级，不能在同一个动作字段里混用。

例如高层目标是世界 `(3, 0)` 米，机器人在 `(2, 0)` 米。它表示“往那个位置移动”，不是“以 3 米/秒前进”。如何得到速度，如何避障，如何处理执行不了的动作，需要明确交给哪个模块。接口说明见[机器人学习概览](../robotics/index.md)。

## 建议实验顺序

1. 固定随机种子，建立少量羊只、无障碍的最小场景。
2. 实现一个规则策略，作为后续学习策略的比较基线。
3. 根据动作空间选择候选算法：少量离散动作可比较 DQN、PPO；连续指令可比较 PPO、TD3、SAC。先明确共同的评估条件，再安排学习实验，分别记录奖励项与终止原因。[查看算法学习路线](../rl/index.md)。
4. 改变羊只数量、初始分布和行为参数，检查泛化表现。
5. 接入 [视觉估计](../vision/index.md)，评估观测误差和延迟的影响。

## 评估指标

- **成功率**：规定时间内达到任务条件的运行占比。
- **到达比例**：进入目标区域的羊只数占总数的比例。
- **完成时间**：成功运行所需时间，同时报告超时情况。
- **聚集程度**：羊群相对中心的距离分布。
- **控制代价**：机器人路径长度、动作变化和碰撞次数。

### 用代码看清“到了几只”与“是否成功”

先只检查**当前这一帧**：目标区是以 `(10, 0)` 为中心、半径 1 米的圆，圆周边界也算进入。下面的小程序只说明几何判断，不训练策略、不连接机器人。

```python
# 三只羊的位置，统一使用世界坐标，单位米。
sheep_positions = [(9.5, 0.0), (10.5, 0.0), (8.0, 0.0)]
goal_x, goal_y = 10.0, 0.0
radius_m = 1.0
inside_count = 0

for x, y in sheep_positions:
    # 先求相对目标中心的横向和纵向差距。
    dx = x - goal_x
    dy = y - goal_y

    # 距离平方 = dx² + dy²。比较平方可避免额外计算平方根。
    # 半径非负，因此与 radius_m² 比较和与距离比较含义相同。
    if dx * dx + dy * dy <= radius_m * radius_m:
        inside_count += 1

# 本例已约定羊的数量大于零；无目标数据应单独处理，不冒充成功。
total = len(sheep_positions)
all_inside_now = inside_count == total
print(f"当前进入：{inside_count}/{total}")
print(f"当前全部进入：{all_inside_now}")
```

预期输出：

```text
当前进入：2/3
当前全部进入：False
```

前两只离中心都是 0.5 米，第三只离中心 2 米，所以只计入两只。这个程序尚未检查“保持 3 秒”，因此即便 all_inside_now 为 True，也只说明本帧全部在内。完整成功判定还需要连续记录时间；一旦有羊离开，连续保持时间应按任务定义重新计算。

本例羊群中心的 x 为 `(9.5 + 10.5 + 8)/3 ≈ 9.33`，离目标中心约 0.67 米，也在圆内。可见“中心在目标区”与“每只羊都在目标区”确实不同。

### 连续保持 3 秒，不是数到 3 帧

先用时间表理解计时。以下“全部进入”指该采样时刻每只羊都在区域内，且所有位置数据有效；使用同一实验时钟：

| 时间 | 本次检查 | 当前这一段从何时开始 | 从段开始到本次采样的时长 |
| --- | --- | --- | --- |
| 1 秒 | 全部进入 | 1 秒 | 0 秒 |
| 2 秒 | 全部进入 | 1 秒 | 1 秒 |
| 3 秒 | 有羊离开 | 清空开始时间 | 重新计时 |
| 4 秒 | 全部进入 | 4 秒 | 0 秒 |
| 5 秒 | 全部进入 | 4 秒 | 1 秒 |
| 6 秒 | 全部进入 | 4 秒 | 2 秒 |
| 7 秒 | 全部进入 | 4 秒 | 3 秒 |

如果任务采用“连续有效采样均在内，首次在内到当前采样相隔至少 3 秒”的判定，并约定采样间隔及允许的数据缺口，就在 7 秒满足这个**采样判定**。第一次进入的那一帧时长为零，不能先凭空加上一个采样间隔；离开后旧的保持时间也不能接着累计。若使用 10 Hz，3 帧通常只跨 0.2 秒；30 次间隔才是 3 秒。

只有离散采样还不能证明两帧之间绝未离开。仿真可按每个物理步检查，真实系统则应说明检查频率、测量误差和缺失处理。数据丢失时不能当成“还在里面”：一种保守规则是中断当前计时，恢复有效数据后重新开始；如果采用别的规则，应同样写清。这样论文里的“保持 3 秒”才对应可核对的判定，而不是一个未说明的计数器。

## 实验记录清单

??? example "小练习：中心到目标了，任务一定成功吗？"

    不一定。羊群中心是位置平均数，羊可能分散在目标两侧，甚至都不在区域内。必须按约定检查每只羊是否进入目标区及保持时间，再判断成功；不能只看中心距离。

### 用一个小例子说清“成功”

假设一幕有 10 只羊，时间上限 60 秒，约定“全部进入目标区，并连续保持 3 秒”才成功。最后一帧有 8 只在区域内，**到达比例为 8/10 = 80%，这一幕仍未成功**。羊曾经进入又离开，也不能按这个定义计为成功。

还要说明**何时统计**：到达比例是最终一帧、某个固定时刻，还是整个运行中的最大比例？假设 30 秒曾有 10/10 只进入、最后只有 8/10，最大比例 100% 与最终比例 80% 可以同时成立。它们不能混用，也都不能代替保持时长检查。若成功一发生就结束该幕，完成时间应记到保持条件真正满足的时刻，而不是第一只或最后一只刚跨入区域的时刻。

若 20 次独立评估有 14 次成功，成功率是 70%。完成时间应标明只统计成功的 14 次，并同时报告 6 次失败及超时原因，避免隐藏难例。这里的数字只是演示指标口径，不是实际实验结果。

比较方法时保持相同初始场景集合、时间上限与成功定义；同时报告训练预算、评估种子和成功次数。奖励提高不必然意味着羊群成功到达，奖励曲线与任务指标要分开看。

每次实验保留场景配置、代码版本、随机种子、训练步数、奖励权重、评估次数与失败案例。先观察失败发生在哪个环节，再决定下一次只改变哪一个变量。

### 怎样设计第一次可比较的评估

先准备固定的几组初始位置，写清羊的行为参数、目标区、时间上限与成功规则。让一个容易理解的规则策略作为**基线**，即后续方法要比较的参照。规则策略也要记录失败，不能只保存表现最好的一次。

之后比较学习策略时，使用同一组评估场景和指标。训练种子控制一次训练过程的随机设置，评估种子控制测试场景中的随机因素；两者用途不同。重复多个训练种子，可以观察算法是否依赖偶然训练结果；每个策略再测试多个场景，可以观察场景变化的影响。

| 看到的失败现象 | 先查什么 | 一次只改一个因素的例子 |
| --- | --- | --- |
| 羊群中心前进，但总有一只掉队 | 观测是否看见掉队个体、评价是否只看中心 | 固定策略，检查完整个体记录 |
| 仿真顺利，视觉输入后失效 | 观测延迟、定位误差、丢失处理 | 单独增加已知大小的观测延迟 |
| 策略输出合理，机器人轨迹不跟随 | 坐标映射、动作限制、控制接口 | 用固定动作检查请求与实际运动 |
| 总奖励增加，成功率没有提高 | 奖励是否只鼓励局部行为 | 分别画每项奖励和任务成功指标 |

以上是实验设计和排查方法，尚未报告任何实际效果。读懂每一个字段与指标，才有条件解释后面的一条训练曲线。
