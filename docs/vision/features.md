# 07 · 特征与匹配：怎样在两张图里找相似的小地方

给一本有封面图案的书拍两张照片：第二张稍微向右移动，还转了一点角度。怎样猜出第一张左上方的图案，在第二张哪里？直接比较同一个像素位置往往没用，因为图案已经移动了。一个常见思路是：先挑容易辨认的小位置，再描述这些位置附近的外观，最后寻找描述相似的候选。

!!! tip "学习目标与前提"

    先读 [05 · 滤波与边缘](filtering.md) 和 [06 · 二值图与连通区域](regions.md)。本课先解释特征点与描述子，再用自造的八位数据手算匹配，不要求先会线性代数。

    代码只演示描述子比较和候选筛选，不包含从真实图像提取 ORB，也不需要安装 OpenCV。

## 1. 看图：位置、描述、匹配是三件事

![先在图中选择局部特征，再记录描述子，比较描述子距离并检查候选是否含糊](../assets/learning/cv-features.svg){ .learning-figure }

[打开大图](../assets/learning/cv-features.svg)

| 概念 | 本课中的含义 | 容易混淆的地方 |
| --- | --- | --- |
| 关键点 / keypoint | 一个位置及尺度、方向等属性 | 不是整张图像的类别 |
| 描述子 / descriptor | 关键点附近外观的数值摘要 | 不是只存 `(u,v)` 坐标 |
| 匹配 / match | 提出两个描述子可能对应的关系 | 相似不保证来自同一真实位置 |
| 几何验证 | 检查多组对应关系能否满足某个场景模型 | 需要说明模型前提 |

可以把关键点想成“书封上值得做记号的位置”，把描述子想成“写下附近图案有什么特征”。但它没有人的理解能力：重复的格子、相似的字母，都可能留下相近的描述。

## 2. 为什么不随便选一块白墙

想象在照片上放一个很小的窗口，轻轻向左右、上下挪动，再比较窗口中的灰度。

- 在均匀白墙上，往哪个方向挪都差不多，不容易知道原位置。
- 在一条很长的直线中段，沿直线方向挪动，内容可能变化很小。
- 在一个明显的拐角附近，往多个方向挪动都更容易改变图案，位置通常更容易区分。

Harris 角点等方法把这种局部变化写成数值评分。“角点”是对局部图像变化的描述，不要求它一定是现实物体的几何拐角；印在纸上的十字交叉处也能有明显响应。更完整的推导可查 [OpenCV Harris 角点教程](https://docs.opencv.org/4.11.0/dc/d0d/tutorial_py_features_harris.html)。

实际算法还会考虑邻域大小、筛选阈值、局部最大值等条件。不要认为“找到更多点”一定更好：同一区域密密麻麻的相似点，可能增加重复匹配，却没有提供更多独立线索。

## 3. 描述子：把小图案变成可比较的数据

一种容易理解的二进制描述思路是：在小邻域中挑两处亮度，比较谁大，把结果写成 0 或 1；用多组比较得到一串位。

例如本例人为规定：“第一个亮度小于第二个记 1，否则记 0”。三组亮度 `(20,80)、(90,30)、(50,50)` 就得到 `100`。等号如何处理也是规则的一部分，不能省略。

这只是用来理解比较的玩具描述子，**不是 ORB 的完整实现**。实际描述子需要设计采样位置，并考虑方向、尺度、噪声等因素。ORB 结合 FAST 关键点与经过改进的 BRIEF 描述思路，使用图像金字塔并处理关键点方向；这些措施提高特定变化下的可用性，并不保证任意视角、模糊和光照条件下都能正确匹配。[OpenCV ORB 教程](https://docs.opencv.org/4.11.0/d1/d89/tutorial_py_orb.html)

### 比较坐标为什么不等于比较外观

第一张图的某个角点在 `(100,60)`，第二张可能在 `(130,65)`。坐标很近的另一点，外观却可能完全不同。描述子距离问的是“记录的外观差多少”，图像坐标距离问的是“画面上隔多远”，两者单位和作用都不同。

## 4. 手算汉明距离：数有多少位不同

本课使用八位字符串表示描述子。汉明距离就是逐位比较后，不相同的位置数量：

$$d_H(a,b)=\sum_{i=1}^{n}\mathbf{1}[a_i\ne b_i]$$

| 符号 | 含义 |
| --- | --- |
| $a,b$ | 两个长度相同的位串 |
| $n$ | 位数，本课等于 8 |
| $a_i,b_i$ | 两串在第 $i$ 个位置的位 |
| $\mathbf{1}[\cdot]$ | 方括号里的判断为真记 1，否则记 0 |
| $d_H$ | 把不同位置数出来，数值越小表示位串越相似 |

以查询 `10110010` 为例：

| 候选 | 位串 | 不同位数 |
| --- | --- | --- |
| A | `10110011` | 1 |
| B | `11100010` | 2 |
| C | `01001101` | 8 |

A 比 B 更接近。候选非空且距离有效时，最近邻会选出一个最接近的候选；但即使所有候选都很不相像，仍可能选出一个。**被选中，不代表找到了真实对应。**

对于默认两点比较方式的 ORB，OpenCV 匹配常用 `NORM_HAMMING`；若 `WTA_K` 为 3 或 4，则要使用对应的 `NORM_HAMMING2`，不能只看“ORB”这个名字就忽略配置。[OpenCV 特征匹配教程](https://docs.opencv.org/4.11.0/dc/dc3/tutorial_py_matcher.html)

## 5. 比值筛选：最佳候选是否明显领先

设最近候选的距离是 $d_1$，第二近是 $d_2$。本课选择教学门槛 $r=0.75$，要求：

$$d_1<r\,d_2$$

$r$ 是无单位的比例门槛，不是“正确率 75%”。这一规则希望最佳候选比第二名明显更接近。上例 `1<0.75×2=1.5`，通过筛选。如果前两名距离都是 1，则 `1<0.75` 不成立，说明候选很含糊。

实际门槛需要按数据和描述子评估。本课采用乘法形式，避免直接除以零：若两个候选都完全相同，$d_1=d_2=0$，严格不等式不成立，应拒绝这次含糊匹配。候选不足两个时，也没有足够信息执行本规则。

通过比值筛选仍不是可靠身份认证。一个错误候选也可能明显领先其他更差的候选，需要进一步检查距离范围、场景约束和多点几何一致性。

## 6. 完整代码：比较、排序、筛选

下面的位串都由我们手写，专门用来展示正常、歧义和数据不足三种情况。

```python title="八位描述子候选筛选 · 独立教学示例"
def hamming_distance(first, second):
    # 本例只接受等长且非空的 0/1 字符串。
    if not first or len(first) != len(second):
        raise ValueError("描述子必须非空且等长")
    if any(bit not in "01" for bit in first + second):
        raise ValueError("本例描述子只能含 0 和 1")

    # zip 把相同位置的两个字符配成一对；不同则计数加 1。
    count = 0
    for left, right in zip(first, second):
        if left != right:
            count += 1
    return count


def choose_candidate(query, candidates, ratio=0.75):
    if not 0.0 < ratio < 1.0:
        raise ValueError("本例 ratio 必须在 0 与 1 之间")
    if len(candidates) < 2:
        return "候选不足两个，暂不匹配"

    # 每项保存 (距离, 名称)；key 明确要求按距离从小到大排。
    ranked = [(hamming_distance(query, bits), name)
              for name, bits in candidates]
    ranked.sort(key=lambda item: item[0])
    best_distance, best_name = ranked[0]
    second_distance, _ = ranked[1]  # 下划线表示本处不使用第二名名称。
    if best_distance < ratio * second_distance:
        return (f"候选={best_name}, 最近={best_distance}, "
                f"次近={second_distance}, 通过比值筛选")
    return f"最近={best_distance}, 次近={second_distance}, 候选含糊"


query = "10110010"
normal = [("A", "10110011"), ("B", "11100010"), ("C", "01001101")]
ambiguous = [("D", "10110011"), ("E", "10110000")]
duplicate = [("F", query), ("G", query)]

for name, bits in normal:
    print(f"距离 {name}: {hamming_distance(query, bits)}")
print(choose_candidate(query, normal))
print(choose_candidate(query, ambiguous))
print(choose_candidate(query, duplicate))
print(choose_candidate(query, normal[:1]))
```

预期输出：

```text
距离 A: 1
距离 B: 2
距离 C: 8
候选=A, 最近=1, 次近=2, 通过比值筛选
最近=1, 次近=1, 候选含糊
最近=0, 次近=0, 候选含糊
候选不足两个，暂不匹配
```

`zip` 对齐两串的位置，因此先检查长度，避免不等长时只比较较短的一部分。`lambda item: item[0]` 是一个短函数：拿到一项，返回这项的第一个值，也就是距离。它只告诉排序函数按什么排序，没有改变距离公式。

`ranked[0]` 表示排序后的第一项，`ranked[1]` 为第二项。两者与描述子内部的第一个、第二个位不是同一层数据。

## 7. 双向检查与几何验证，还检查了什么

**双向最近邻检查**问：“A 图的点 p 最喜欢 B 图的点 q，q 在反向比较时也最喜欢 p 吗？”这与“第一名是否领先第二名”的比值筛选不同。双向检查也可能保留错误匹配，尤其是重复图案；不要把两个方法当成数学上等价。

**几何验证**再问：“多组匹配能否同时解释为某种合理的图像变换？”例如拍摄同一张近似平面纸张，在适当前提下可用平面单应性验证对应关系。但任意三维场景、明显遮挡、相机和物体分别运动时，不能强行用同一张平面解释所有点。几何模型依赖场景前提，本课先停在候选和筛选，不把几条相似连线误报为已经验证。

??? example "展开参考答案"

    不通过。严格小于不接受等号。若改成 0.8，则 `6<6.4` 通过，但两个距离都可能来自错误对应；比值只衡量相对领先程度，不提供真实性证明。对八位数据，距离 6 也表示大部分位不同，应结合任务检查绝对距离和几何一致性。
