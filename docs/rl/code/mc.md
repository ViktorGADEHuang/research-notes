## 示例背景

**语言：Python 3.12 或以上；依赖：仅标准库；实现方式：手写更新。**

环境是一条走廊：非终止状态为 1～5，起点为 3，左端 0 奖励 −1，右端 6 奖励 +1，中间每步奖励 −0.01。动作 0 向左，动作 1 向右。这是帮助理解算法的小环境，不是羊群仿真。

## 先只看三条奖励怎样变成回报

```python
# 一局的三次奖励；为便于口算，本小片段折扣用 0.9。
rewards = [-0.01, -0.01, 1.0]
gamma = 0.9
returns = [0.0] * len(rewards)  # 先留三个位置，分别存每一时刻的回报。
total = 0.0                     # 终止以后没有奖励，所以从 0 倒推。
for t in reversed(range(len(rewards))):  # t 的顺序是 2、1、0。
    total = rewards[t] + gamma * total  # 先算 1，再算 0.89，再算 0.791。
    returns[t] = total                  # 放回原时间位置，不把顺序颠倒。
```

最终 `returns` 按时间顺序是约 `[0.791, 0.89, 1.0]`。这个片段只结算一局，还没把结果加入跨局平均。

| 完整代码变量 | 保存什么 | 保留多久 |
| --- | --- | --- |
| `episode` | 每一步的 `(动作前状态, 随后奖励)` | 这一局 |
| `returns` | 与 episode 同长度的各时刻回报 | 这一局 |
| `visited` | 这一局已经计入平均的状态编号 | 每局清空 |
| `counts`、`values` | 各状态累计次数、平均回报 | 所有回合之间保留 |

为何先倒序算回报，再正序挑首次访问？假如状态 3 出现两次，首次访问指时间最早的那一次；如果倒着走并把首次碰见当作首次访问，挑出的会是最后一次。完整代码特意分成两段循环来避免这个混淆。

## 同一位置出现两次时，到底统计哪一次

仍用小片段的折扣 0.9，假设这一局按 3 → 4 → 3 → 4 → 5 → 6 行动。奖励列表为 [−0.01, −0.01, −0.01, −0.01, 1]：

| 时间 t | 动作前位置 | 从此处往后的回报 | 正序检查 visited 的结果 |
| --- | --- | --- | --- |
| 0 | 3 | 0.62171 | 3 尚未统计，计入一次 |
| 1 | 4 | 0.7019 | 4 尚未统计，计入一次 |
| 2 | 3 | 0.791 | 3 已在集合中，跳过 |
| 3 | 4 | 0.89 | 4 已在集合中，跳过 |
| 4 | 5 | 1 | 5 尚未统计，计入一次 |

因此位置 3 这一局收到的 MC 样本是 **0.62171**，不是 0.791。先倒序得到所有回报，随后从 t=0 正序挑首次访问；两个方向承担不同任务。虽然不把第二次的 3 再计为样本，第一次的回报仍包含后面绕回 3 的经历，没有把重复经过的奖励删掉。

完整脚本把折扣改为 0.95，所以数字会变；访问顺序和筛选规则不变。

## 完整代码

```python title="mc · 完整学习代码"
"""标准库教学代码：对照注释理解更新过程，无需运行。"""
import random

# 固定随机数起点，便于对照不同步骤；随机种子不保证跨硬件完全一致。
rng = random.Random(7)
# gamma 给未来奖励打折；MC 的增量平均步长是 1 / 访问次数。
gamma = 0.95

# 小走廊模型：输入当前位置与动作，返回下一位置、奖励、终止标记。
def step(state, action):
    # 调用者只传动作 0 或 1；先按动作找到下一位置。
    if action == 1:
        ns = state + 1  # 向右。
    else:
        ns = state - 1  # 向左。
    # 两端才是真正终点；0、6 不再作为下一次 step 的输入。
    done = ns in (0, 6)
    # 奖励描述刚发生的结果；进入终点时不再额外扣中间步进代价。
    if ns == 6:
        reward = 1.0
    elif ns == 0:
        reward = -1.0
    else:
        reward = -0.01
    return ns, reward, done


# V 表按状态存分数；两个终止位置也占位，但不更新它们。
# 下标就是状态编号；0 与 6 作为终点占位，非终止位置是 1 到 5。
values = [0.0] * 7
# 记录每个状态被纳入平均的次数，用于首次访问 MC。
counts = [0] * 7
# 采集 10000 个完整回合；只增加评估样本，不改变随机策略。
# 这些数量是教学设置，不构成收敛保证。
for _ in range(10000):
    # 一幕从状态 3 开始，并记录这一幕经历的数据。
    s, episode = 3, []
    # 持续与环境交互，直到走到左端或右端。
    while s not in (0, 6):
        a = rng.randrange(2)  # 只评估随机策略，不改进策略
        # 执行一次动作，获得下一状态、奖励和真正终止的标记。
        ns, reward, done = step(s, a)
        # 保存这一时刻的数据，方便在结束后从后往前计算回报。
        episode.append((s, reward))
        # 先保存动作前的位置，再推进当前位置；本局学习要等回合结束。
        s = ns
    # 只创建本局的回报表；最后一步之后回报为 0，便于从末尾递推。
    returns, total = [0.0] * len(episode), 0.0
    # 从最后一步倒推 G：当前奖励 + gamma × 后面已经算好的回报。
    for t in reversed(range(len(episode))):
        total = episode[t][1] + gamma * total
        returns[t] = total
    # 同一幕内用集合标记出现过的状态，保证首次访问 MC 不重复计数。
    visited = set()
    for t, (s, _) in enumerate(episode):
        if s not in visited:
            visited.add(s)
            counts[s] += 1
            # 用增量平均吸收这一幕的回报；步长是 1 / 访问次数。
            values[s] += (returns[t] - values[s]) / counts[s]
print("Random-policy values:", [round(x, 3) for x in values[1:6]])
```

## 对照公式看代码

从回合结尾反向计算 `returns`；`visited` 只统计第一次访问；`counts` 让更新等价于历史回报均值。

## 如何理解输出

输出均匀随机策略下的价值，不是最优价值。右侧通常为正，左侧通常为负。位置 3 也不一定为 0：左右终点的正负收益可以在对称策略下相互抵消，但中间每步仍扣 0.01，平均回报会受这些代价影响。

随机采样结果还会波动，因此这里不编造一组“必定打印”的数。完整代码使用折扣 0.95，小片段使用 0.9，只是为了让倒推更容易口算。

**按这几步做**：

1. 按 t=2、1、0 的顺序填回报。
2. 把新回报按原时间顺序放回 returns。
3. 更新平均时先用次数 2 还是 3？说明 visited 何时清空。

??? example "对照完整推理"

    终点之后回报为 0，最后一步得到 1；前一步为 −0.01 + 0.9×1 = 0.89；再前一步为 −0.01 + 0.9×0.89 = 0.791。returns 的顺序为 [0.791, 0.89, 1]，计算倒序不改变记录时间顺序。

    次数先从 2 加到 3。新均值 = 0.5 + (0.791−0.5)/3 = 0.597。visited 每局清空，因为首次访问指每局第一次；values 与 counts 跨局保留。
